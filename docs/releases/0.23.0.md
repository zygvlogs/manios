ManiOS 0.23.0 makes **FAT volumes writable**: the kernel now writes
them itself, and ManiDOS's `DEL`, `MD`, `RD`, `REN` and `COPY` onto a
file write to the disk instead of saying "Access denied". `> FILE`
writes a file, libc grows `unlink`, `mkdir`, `rmdir`, `rename`,
`remove` and `mkstemp`, and OpenBSD's `sed -i` and `tee FILE` work.
ManiOS is an independent operating system for i386 PCs with its own
kernel (ZKT), userland, desktop (ManiDE), disk operating system
(ManiDOS) and drivers.

Until this release ManiOS could read a FAT volume but not write one:
every program that tried to make a file got EROFS. The writer lives in
the kernel (`zkt/fs/fat.c`) and every change reaches the device before
the call returns -- there is no dirty cache to flush -- so both copies
of the FAT are written, one after the other, and what a program wrote
can be read back from the image with mtools straight afterwards.

This is a **pre-release**, tested in QEMU.

## What's new

- **The kernel's FAT writer.** Clusters are allocated and linked,
  directory entries are created, emptied and renamed, long-name slots
  beside a changed entry are dropped, and a full disk answers
  `ENOSPC`. Only FAT12 and FAT16 (FAT32 still isn't mounted).
- **The syscalls for it, ABI version 2.** `SYS_UNLINK`, `SYS_MKDIR`,
  `SYS_RMDIR` and `SYS_RENAME`, plus `O_CREAT`, `O_TRUNC` and `O_EXCL`
  for `SYS_OPEN`. Programs built against the older ABI still run: the
  kernel still takes version 1.
- **ManiDOS writes.** `DEL`/`ERASE`, `MD`/`MKDIR`, `RD`/`RMDIR`
  (empty directories only), `REN`/`RENAME` in one directory, `COPY`
  onto a file -- and one name alone, copied into the current directory
  -- and `> FILE` / `>> FILE` writing files. Each refuses in DOS's own
  words: "Access denied - NEWDIR is a directory", "File not found",
  "Duplicate file name or file not found", "The file cannot be copied
  onto itself", "Insufficient disk space".
- **A POSIX file layer in libc.** `open()` takes `O_CREAT`, `O_TRUNC`
  and `O_EXCL`; `unlink`, `rmdir`, `rename` and `mkdir`; `remove()`
  and `mkstemp()`; `fopen`/`freopen`/`fdopen` emptying a file for `"w"`
  and seeking to the end for `"a"`.
- **The OpenBSD tools can write.** `sed -i` (a temporary file, then a
  rename over the original) and `tee FILE` work on a FAT volume.

## Changed

- The refusal to write now names the drive rather than the system:
  "Access denied - that drive is read-only", for A:, Z:, a CD and a
  write-protected floppy alike -- while `FORMAT`, `FDISK`, `LABEL` and
  `SYS` still aren't in ManiDOS, and `CHKDSK /F` says it has no repair
  rather than that the drives are read-only (they aren't any more).

## Known limits

Only FAT12 and FAT16, and only a volume ManiOS has mounted; a volume
whose device takes no writes -- A:, Z:, a CD, a write-protected floppy
-- says so. A long name is written under its `~1` alias with no
long-name entry beside it, so two long names that share their first six
letters and their extension are told apart when they are made but not
when they are asked for. No `FORMAT`, `FDISK`, `LABEL` or `SYS`, no
`CHKDSK /F` repair, no `DEL /P /S /Q`, no wildcards in `REN`; a rename
stays within one directory. Files have no times, so `DIR` shows no
dates. See [the milestone's notes](https://github.com/zygvlogs/manios/blob/v0.23.0/docs/milestones/M22-fat-writes.md#known-limits).
Otherwise as 0.22.0: no USB, Intel HD Audio, NVMe or SCSI; no floating
point in programs; no signals. None of ManiOS's drivers has met real
hardware other than the one that found a gap in an earlier release
yet: reports are welcome.
