ManiOS 0.26.0 adds DOS EXEC child-process support and includes the DOS
compatibility and installer fixes made since 0.25.0. This is a pre-release
for i386 PCs, tested in QEMU.

## DOS EXEC

- `INT 21h AX=4B00h` loads and runs COM and MZ executables from DOS paths.
- Children receive their own allocation, PSP, environment, command tail,
  default FCBs, and inherited handles. Nested execution is supported.
- Child termination restores the parent; `AH=4Dh` returns the exit status.
  Child-owned memory and handles are reclaimed.
- MZ relocation uses the child's load segment. Zero-minimum/maximum MZ
  images load at the high end of their allocation.
- Missing files, invalid formats, insufficient memory, and unsupported
  EXEC subfunctions report DOS errors without replacing the parent.

## Other changes since 0.25.0

The release includes the committed DOS directory creation/removal, per-drive
current-directory, file-search, persisted timestamp, FAT directory-growth,
video-status polling, PIT channel 2, and PC-speaker control fixes. These
changes allowed Windows 1.01 setup to complete on the saved test disk.

## Windows 1.01 status

**Setup completes; the Windows desktop still does not run.** EXEC now enters
`WIN100.BIN`, removing the original missing-EXEC blocker. Windows then rejects
the emulated DOS 4.00 version. A diagnostic version override reaches the
unsupported DOS-internal list-of-lists service (`AH=52h`). This release does
not spoof that service or ship the diagnostic override.

The saved Windows installation is preserved. Microsoft binaries and disk
images are not included in this release.

## Validation and limits

Generated regression programs cover child COM/MZ execution, nested return,
status retrieval, PSP/environment inheritance, inherited handle isolation,
parent stack/DTA restoration, private-handle exclusion, memory reclamation,
and load failures. The EXEC harness passes AddressSanitizer and
UndefinedBehaviorSanitizer; a QEMU child program returns status 42 to its parent.

Two existing graphics checks fail when restoring text after VGA mode 13h.
Both failures reproduce on the saved pre-change kernel; this release does
not fix that graphics issue. The low-memory boot test now accepts either
the physical-allocator or user-program exhaustion point as the embedded
archive grows, while still checking the visible panic and halt.

TSRs, load-only/overlay EXEC subfunctions, protected mode, and DOS extenders
remain unsupported. Direct DOS-internal structures and arbitrary guest
interrupt hooks are not a complete DOS compatibility layer.
