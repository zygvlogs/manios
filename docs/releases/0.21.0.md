ManiOS 0.21.0 brings **`gfx=auto`**: a real display adapter's own
linear framebuffer, for `manide` and `gfxdemo` on real hardware, not
only emulators. ManiOS is an independent operating system for i386 PCs
with its own kernel (ZKT), userland, desktop (ManiDE), disk operating
system (ManiDOS) and drivers; see
[0.20.0](https://github.com/zygvlogs/manios/releases/tag/v0.20.0).

Found within hours of 0.20.0 booting on a real machine for the first
time: without QEMU's, VirtualBox's or VMware's emulator-specific
graphics registers, `manide` had nothing to draw to. `gfx=auto` on the
boot line has ManiOS's own boot loader ask the real card's own VESA
BIOS for a linear framebuffer before ManiOS starts.

This is a **pre-release**, tested in QEMU (on three different display
adapters, none of them QEMU's own Bochs-compatible one).

## What's new

- **`gfx=auto`** on the boot line: the boot loader probes the display's
  VESA BIOS Extensions (2.0 or later) for the biggest 32-bit-colour
  linear-framebuffer mode up to 1024x768, and sets it before ManiOS
  starts. `manide` and `gfxdemo` then draw to it exactly as to a Bochs
  VBE adapter's.
- Left out (the default), or given anything but `auto`: nothing
  changes -- no probe, no different boot, exactly as 0.20.0.
- Where a Bochs VBE adapter is also there, it is still preferred (any
  size, changed at will); `gfx=auto`'s own mode goes unused.

```
graphics: VESA 1024x768 found
```

Guide: [docs/install.md](https://github.com/zygvlogs/manios/blob/v0.21.0/docs/install.md#gfxauto-a-real-adapters-own-linear-framebuffer).

## Known limits

The mode is set once, at boot: no changing its size, and no way back
to text mode that is sure to work on every card (M21's own notes,
[docs/milestones/M21-vesa-lfb.md](https://github.com/zygvlogs/manios/blob/v0.21.0/docs/milestones/M21-vesa-lfb.md#known-limits)).
32-bit colour only, at most 1024x768. Otherwise as 0.20.0: no USB,
Intel HD Audio, NVMe or SCSI; ManiOS's FAT drives are read-only to
files; no floating point in programs; no signals. None of ManiOS's
drivers, this one included, has met real hardware other than the one
that found this gap yet: reports are welcome.
