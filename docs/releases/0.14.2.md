ManiOS 0.14.2 fixes a garbled graphics screen in VirtualBox. ManiOS is
an independent operating system for i386 PCs with its own kernel (ZKT),
userland and desktop; see
[0.14.0](https://github.com/zygvlogs/manios/releases/tag/v0.14.0).

This is a **pre-release**, tested in QEMU; the VirtualBox fix below is
made from a VirtualBox screenshot and not yet confirmed in VirtualBox
itself -- reports welcome.

## What changed

- **Graphics in VirtualBox.** After a change of graphics mode -- for
  example `gfxdemo` (640x480) after the desktop (800x600) -- VirtualBox
  showed the new picture in only one row in five, with a staircase of
  leftovers from the previous screen in between. Measured on the
  screenshot: VirtualBox had repainted just the first 640 bytes of every
  3200, which is the previous mode's line length, and nothing drew those
  areas again. ManiOS now:
  - sets the mode's registers in the order VirtualBox's own VGA BIOS
    uses, giving the line length outright;
  - for a second and a half after each mode change, writes every page of
    the frame again, unchanged, so that the emulator repaints all of it
    once it has taken the new mode. (On other machines this is a few
    hundred reads and writes, and changes nothing.)

## Known limits

As in 0.14.1: no network in VirtualBox (ManiOS knows only the NE2000);
no writable root filesystem; no ^C; ZRP messages are not encrypted;
BIOS only, PIO disks only.
