ManiOS 0.17.1 settles the three changes 0.17.0 asked you to know about,
and makes room for ManiOS to keep growing. ManiOS is an independent
operating system for i386 PCs with its own kernel (ZKT), userland and
desktop; see [0.17.0](https://github.com/zygvlogs/manios/releases/tag/v0.17.0)
for its tools from OpenBSD.

This is a **pre-release**, tested in QEMU.

## What's changed

- **ABI version 2, done properly.** 0.17.0 made seeking a pipe fail
  (ESPIPE), as POSIX requires, but kept the system call ABI at version
  1. Now the ABI is version 2, and the kernel answers each program as
  its version promised: programs built for version 1 still see the old
  behaviour. Everything in ManiOS 0.17.1 is built for version 2.
- **Room to grow.** ManiOS gets bigger with every program it gains, and
  its boot loader had a ceiling: it always put the boot area at 4 MiB,
  so the kernel (which carries every program in `/bin`) had to fit
  below that, and the kernel's first page table mapped only 4 MiB. Now
  the loader puts the boot area just past the kernel, wherever that
  ends, and the kernel maps 16 MiB from the start. A test build with a
  7 MiB kernel boots.
- **The loader says what ManiOS needs.** "not enough memory: ManiOS
  needs 6 MiB" is now worked out from ManiOS's size, so it stays true
  as ManiOS grows. 6 MiB machines still boot (tested).
- `malloc(0)` stays as in 0.17.0: a pointer of its own, as on the BSDs.

## Known limits

As 0.17.0: ManiOS can't create, rename or remove files yet; no floating
point in programs; no signals; the "C" locale only; BIOS only, PIO disks
only. The kernel image can grow to nearly 16 MiB, and the boot area to
16 MiB.

licenses (see `NOTICES.txt`).
