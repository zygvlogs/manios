# PIT0 / PIC IRQ0 / BIOS timer implementation — 2026-10-24

## Life2 mechanism established first

Life2 does not merely poll the BIOS clock or wait for INT 1Ch. Its BASIC
SOUND runtime installs an INT 08h handler, saves the preceding BIOS vector
in INT F0h, and programs PIT0 with divisor 2048. The sound wait at
111E:0B9F–0BAB polls DS:0043. The installed timer handler decrements that
word, feeds the sound queue, acknowledges the master PIC and chains to the
saved BIOS handler once per 32 pulses. 2048 × 32 = 65536, retaining the
normal BIOS clock rate when the application chains correctly.

The previous implementation had PIT counter state but no delivered IRQ0,
and the main loop discarded installed guest vectors by immediately popping
the interrupt frame. Thus accepting port writes or updating BIOS clock
memory could not release this wait. The earlier synthetic-IRQ experiment
isolated this dependency; the new native test needs no synthetic injection.

## General implementation

- Wall-time milliseconds feed the 1,193,182-Hz PIT0 oscillator with fractional
  clocks retained. Deterministic tests can call `dos_timer_advance` directly.
- PIT0 binary modes 0, 2 and 3 generate terminal/rising edges. Low/high reload
  transfers, zero=65536, count reads and unread count latches remain supported.
- Edges latch IRQ0 in a minimal master PIC. Port 21h masks delivery without
  clearing pending requests. Port 20h supports IRR/ISR reads and non-specific
  or IRQ0-specific EOI. One pending edge is retained; additional edges coalesce.
- CPU interrupt acknowledgement occurs only with IF set and outside the
  one-instruction STI / MOV SS / POP SS interrupt shadow. In-service IRQ0
  blocks further delivery until EOI. Acknowledgement builds a real INT frame.
- `dos_int` returns CPU_GUEST for a resolved nonzero IVT handler; the runner
  executes guest instructions and their IRET rather than discarding the frame.
- BIOS ROM stubs provide the initial INT 08h and INT 1Ch vectors. Default INT
  08h increments 0040:006C, handles midnight rollover, invokes INT 1Ch, issues
  EOI and IRETs. INT 1Ah observes the same counter. A guest replacement that
  does not chain intentionally prevents BIOS ticks and INT 1Ch callbacks.
- The runner checks elapsed time every 1000 interpreted instructions.

No Life2-specific branch, address check or EXE patch is used in production.
Signed seek handling was left unchanged. Existing local edits were preserved.

## Earlier PIT regression failure

The old failing assertion expected byte IN from port 60h to fault. Port 60h
is already the supported keyboard data port, so that expectation predates
keyboard support. It was unrelated to missing timer IRQs. The refusal test
now uses unsupported port 65h. Opcode tests also mask IRQ0 explicitly so a
pending asynchronous event cannot replace the instruction being tested.
PIT0 counter tests now feed oscillator clocks rather than modifying the
instruction counter; channel 2 remains instruction-clocked.

## Scope limits

This is a bounded PC timer path, not full PIT/PIC emulation. Unsupported:
PIC initialization/remapping/rotation, slave-PIC and other IRQ sources,
PIT1, modes 1/4/5, BCD and 8254 read-back. Timing has millisecond host
quantization and instruction-slice latency; hardware reload-at-period-boundary
behavior is not modeled. Channel 2 remains instruction-clocked and silent.
Blocking host BIOS keyboard calls suspend guest execution/timer servicing,
and HLT still ends the runner rather than sleeping until an interrupt.
BIOS stubs use a private INT F1 trap. Broader Life2 patterns/features and the
isolated startup runtime error need further testing. Life2 remains Partial.
