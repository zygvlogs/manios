# Follow-on architecture after 0.27.0

This development update adds a bounded real-mode 32-bit operand subset.
It does not supply the execution environment of a DOS extender.

## DPMI and protected mode

A future implementation needs explicit execution mode and descriptor state:
CR0.PE, GDT/LDT/IDT, segment selectors with cached base/limit/access/default
operand and stack-size attributes, 32-bit EIP/EFLAGS, exception delivery and
privilege validation. Address-size 67h additionally needs the 32-bit ModR/M
and SIB decoder. Linear memory translation must distinguish conventional
memory, extended allocations and paging from the current 20-bit bus wrap.

The DPMI host must implement discovery (INT 2Fh/1687h), entry/exit transitions,
INT 31h descriptor/memory/vector services, real-mode interrupt simulation,
callbacks, nested exception frames and memory ownership through DOS EXEC.
DOS/BIOS services need validated transfer buffers and protected/real-mode
bridges. Extenders also require VCPI/XMS behavior appropriate to their paths;
a DPMI API stub alone cannot safely run their payloads. Tests should isolate
each mode transition, descriptor violation and callback before trying games.
No DPMI implementation is included here. The interface boundaries follow the
[DPMI 1.0 specification](https://openwatcom.org/ftp/devel/docs/dpmi10.pdf)
and its [INT 2Fh/1687h entry-point contract](https://www.delorie.com/djgpp/doc/dpmi/api/2f1687.html);
the proposed internal decomposition is an implementation plan inferred from
the current ManiOS interpreter.

## Hardware ports and floating point

- PIC mask port 0021h is already backed by the virtual PIC mask and pending
  interrupt arbitration (`dosapi.c`); it must not become an unconditional
  success stub. Existing port/PIT tests exercise the device path.
- VGA CRTC 03D4h is an index port paired with 03D5h. Safe support needs a
  register bank, readable indexes and defined mapping of cursor/start-address
  changes onto the virtual text screen. Merely storing arbitrary writes
  would not establish functional display support.
- CMOS 0070h selects a register and controls NMI masking, paired with 0071h.
  Safe support needs a stable RTC snapshot, status/update-in-progress
  semantics, binary/BCD and 12/24-hour conversions; BIOS INT 1Ah alone is
  not a register-compatible CMOS model.
- FPU-related 00F0h interacts with external-coprocessor interrupt state.
  With no virtual x87 exception state it cannot meaningfully acknowledge
  errors. It remains an explicit unsupported port.
- FWAIT requires a defined pending x87 exception model and coprocessor
  availability semantics. Implementing it as unconditional success would
  conceal missing x87 behavior. Full x87 needs the eight-register stack,
  tags, control/status words, rounding, precise conversions, NaNs, exceptions
  and environment save/restore; reliable validation needs numerical oracles
  and state-level tests. No x87/FWAIT implementation is included.

These are architectural requirements inferred from the current interpreter
and virtual-device boundaries, not claims that affected applications work.

## October 27 evidence and remaining contracts

The interpreter now supports real-mode 32-bit shifts, flags stack operations,
multiply/divide and bit operations. FoxType, LHa, lzop and UnRAR advance to
`0F 01 E0` (SMSW AX), a legal real-mode control-state probe. Group 7 is still
refused because this implementation has no CR0 state; calling all of group 7
“protected-mode only” is imprecise. A future control-state model should define
PE/MP/EM/TS/ET, reset values, legal writes and exception effects before adding
SMSW/LMSW or transitions. Returning a value chosen just to bypass a loader
would not supply its subsequent execution environment.

DOS/32A reaches x87 `DB`; Mahjong still reports DPMI initialization failure.
Directory Maven now reaches CRTC index 0Eh through port 03D4h, the cursor-high
register, so cursor-address/start-address integration is the next display
work. These new stopping points supersede earlier 66h/PUSHFD diagnoses for
the tested binaries; the older reports remain historical evidence.

The BIOS memory query now returns its initialized 640-KiB BDA word. INT 15h
system/extended-memory services explicitly fail (AH=86h/CF=1); XMS and EMS
remain separately allocated pools, not guest-addressable memory above 1 MiB.
The DOS clock follows BIOS ticks but RTC/date and equipment reporting still
need a coherent device model. DOS free-space AH=36h still reports placeholder
geometry for every drive, including absent drives. SPACE's resulting invented
volume totals are a defect, not successful disk-space support. Accurate
reporting requires mounted-volume existence and native free-cluster metadata.

An MD5SUM startup trace reaches missing DOS AH=37h (switch character). A
scratch-only prototype of that service advances to missing AH=60h (canonical
pathname); it does not calculate a checksum. Neither prototype was integrated.
These require documented return conventions, mounted-drive/current-directory
semantics, output bounds and independent regression tests. STATUS 2.01 still
reports more free conventional memory than its displayed 640-KiB total; its
historical Working label must not be treated as validated numeric output.
